# Atlas 研发知识中心技术方案

## 1. 文档说明

本文档描述 Atlas 研发知识中心 MVP 阶段的技术实现方案。方案结合当前产品文档、页面原型、数据模型、接口清单，以及参考项目 `/Volumes/MOVESPEED/project/nexus` 的前后端实现方式制定。

## 2. 技术选型

### 2.1 总体选型

| 层级 | 技术 |
|---|---|
| 前端 | Vue 3、TypeScript、Vite、shadcn-vue 后台模板 |
| 前端状态 | Pinia、pinia-plugin-persistedstate |
| 前端请求 | Axios 封装 |
| 前端路由 | Vue Router |
| 前端图标 | lucide-vue-next |
| 表单校验 | zod、vee-validate，可按复杂度逐步引入 |
| 表格 | 普通表格优先，复杂表格可用 TanStack Table |
| Markdown 编辑 | md-editor-v3 |
| 后端 | Go、Gin |
| ORM | GORM |
| 数据库 | PostgreSQL |
| 登录 | 调用现有登录接口，后端签发本系统 JWT |
| 文件 | 后端代理上传到内部文件服务 |
| 部署 | Docker、Nginx、传统服务器 |

### 2.2 选型原因

- Vue 3 + shadcn-vue：与参考项目一致，适合快速搭内部工具。
- Gin + GORM：结构清晰、上手快，CRUD 开发效率高，适合个人或小团队维护。
- PostgreSQL：支持关系数据、JSON 字段、全文搜索，能支撑文档搜索的 MVP 实现。
- md-editor-v3：Vue 生态成熟，上手成本低，能满足 Markdown 编辑、预览、图片插入需求。
- Docker：传统服务器部署简单，前后端各自镜像，Nginx 统一入口。

### 3.3 登录参考

参考项目登录流程：

1. 前端调用本系统后端 `/auth/login`。
2. 后端调用外部管理系统登录接口。
3. 外部接口返回用户信息、角色和 token。
4. 后端将外部用户 upsert 到本地 `user` 表。
5. 后端签发本系统 JWT。
6. 前端保存 token 到 localStorage。
7. 后续请求通过 `Authorization: Bearer <token>` 访问受保护接口。
8. 后端中间件解析 JWT，将 `userID` 写入 Gin context。

Atlas 研发知识中心沿用该模式。

## 5. 后端设计

### 5.1 后端分层

```text
handler -> service -> repository -> model/database
```

职责：

- `handler`：解析请求、参数校验、获取当前用户、返回响应。
- `service`：业务编排，如文档保存时生成版本、写审计、计算目录。
- `repository`：GORM 查询和事务封装。
- `model`：数据库模型定义。

参考项目中部分逻辑直接在 handler 调 repository。Atlas 研发知识中心模块更多，建议增加 service 层，避免文档、审计、搜索逻辑挤在 handler 中。

### 5.4 响应格式

为复用参考项目前端请求封装，建议沿用：

```json
{
  "code": 200,
  "message": "ok",
  "data": {}
}
```

错误示例：

```json
{
  "code": 400,
  "message": "参数错误",
  "data": null
}
```

注意：

- 当前 `接口清单.md` 中部分示例使用 `code: 0` 表示成功。
- 若复用 `nexus` 的 `ResultEnum.SUCCESS = 200`，应统一改成 `code: 200`。
- 若坚持 `code: 0`，则需要同步修改前端响应拦截器。

### 5.5 登录与认证

后端登录流程：

1. 前端提交用户名、密码等字段到 `/api/v1/auth/login`。
2. 后端调用现有登录接口。
3. 登录成功后解析外部用户信息。
4. 本地 `user` 表按 `external_user_id` upsert。
5. 后端使用 `JWT_SECRET` 签发本系统 JWT。
6. 前端保存 token。
7. 后续接口通过 JWT 中间件保护。

建议配置项：

```text
AUTH_LOGIN_URL=http://auth-service/api/external/login
JWT_SECRET=replace-with-secure-secret
JWT_EXPIRES_HOURS=24
```

JWT claims 建议：

```json
{
  "user_id": 1,
  "external_user_id": "external-10001",
  "exp": 1234567890,
  "iat": 1234560000
}
```

### 5.6 权限预留

第一版只做轻量权限：

- 登录用户默认可查看。
- 编辑、删除、恢复等按钮先按角色或配置控制。
- 管理中心入口只对管理员角色展示。

后续对接权限系统时补充：

- 路由权限。
- 按钮权限。
- 接口权限。
- 数据权限。

MVP 可以先使用 GORM AutoMigrate，但生产建议逐步切换到可追踪迁移脚本。

建议：

## 7. 搜索方案

### 7.1 MVP 搜索

- 文档标题、摘要：`ILIKE`。

### 7.2 文档搜索字段

- `content_md`：原始 Markdown。
- `content_text`：去除 Markdown 标记后的纯文本。

### 7.3 后续扩展

当搜索体验不够或数据量变大时，可接：

- Meilisearch
- OpenSearch
- Elasticsearch

当前阶段不引入独立搜索服务，避免维护成本过高。

## 9. 文件服务方案

### 9.1 上传模式

建议采用后端代理上传：

```text
前端 -> ty-notebook API -> 内部文件服务
```

原因：

- 前端不直接暴露内部文件服务鉴权细节。
- 后端可以统一做文件类型、大小、用户、审计控制。
- 后续切换文件服务时前端无感知。

### 9.2 后端上传接口

```text
POST /api/v1/document-assets
Content-Type: multipart/form-data
```

参数：

- `file`
- `documentId`，可选

限制：

- 支持 jpg、png、webp、gif。
- 单张图片默认不超过 10MB。

### 9.3 内部文件服务配置

预留配置：

```text
FILE_SERVICE_BASE_URL=http://internal-file-service
FILE_SERVICE_UPLOAD_PATH=/api/files/upload
FILE_SERVICE_TOKEN=optional-token
MAX_UPLOAD_SIZE_MB=10
```

实际字段以内部文件服务接口为准。

## 11. 部署方案

### 11.1 部署结构

传统服务器上通过 Docker Compose 部署：

```text
Nginx 前端容器 -> /api/ 反向代理 -> Go API 容器 -> PostgreSQL
```

PostgreSQL 有两种方式：

- 推荐生产：使用已有独立 PostgreSQL 服务。
- 开发/小规模试运行：Docker Compose 内置 PostgreSQL。

### 11.2 前端 Dockerfile

```dockerfile
FROM node:22-alpine AS builder

RUN corepack enable && corepack prepare pnpm@latest --activate

WORKDIR /app

COPY package.json pnpm-lock.yaml ./
RUN pnpm install --frozen-lockfile

COPY . .
RUN pnpm run build

FROM nginx:1.27-alpine

RUN rm /etc/nginx/conf.d/default.conf
COPY nginx.conf /etc/nginx/conf.d/app.conf
COPY --from=builder /app/dist /usr/share/nginx/html

EXPOSE 80

CMD ["nginx", "-g", "daemon off;"]
```

### 11.3 后端 Dockerfile

```dockerfile
FROM golang:1.24-alpine AS builder

WORKDIR /app

COPY go.mod go.sum ./
RUN go mod download

COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-s -w" -o server ./main.go

FROM alpine:3.21

WORKDIR /app

RUN apk add --no-cache ca-certificates tzdata && \
    cp /usr/share/zoneinfo/Asia/Shanghai /etc/localtime && \
    echo "Asia/Shanghai" > /etc/timezone

COPY --from=builder /app/server .

EXPOSE 8080

CMD ["./server"]
```

### 11.4 Nginx 配置

```nginx
server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;

    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml image/svg+xml;
    gzip_min_length 1024;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass         http://api:8080/api/;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }

    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        try_files $uri =404;
    }
}
```

- 后端结构化错误日志。

- 数据库慢查询后续按需开启。

建议后续增加：

## 15. 安全设计

### 15.1 登录安全

- JWT secret 必须来自环境变量。
- token 设置过期时间。
- 生产环境启用 HTTPS。
- 401 时前端清理 token 并跳转登录页。

### 15.2 数据安全

- 私有笔记必须按 `user_id + project_id` 隔离。
- 公共文档不建议存共享密码。
- 操作审计普通用户不可删除。
- 文件上传限制类型和大小。

### 15.3 CORS

生产环境不建议 `*`。

通过环境变量配置：

```text
ALLOWED_ORIGINS=https://ty-notebook.company.com
```

## 16. 技术风险

### 16.1 搜索体验

风险：

- PostgreSQL 模糊搜索和全文搜索可能不如专用搜索引擎。

应对：

- MVP 先使用 PostgreSQL。
- 保留 `search_service`，后续可替换为 Meilisearch/OpenSearch。

### 16.2 文档编辑复杂度

风险：

- Markdown 编辑器、图片上传、目录生成之间存在细节问题。

应对：

- 优先保证保存和展示。
- 图片上传和模板作为 P1。
- 目录可由后端或前端生成，优先后端保存 `toc_json`。

### 16.3 权限扩展

风险：

- 第一版轻权限，后续接权限系统可能影响接口结构。

应对：

- 保留 `visibility`、`permission_scope`。
- 前端按钮权限从一开始封装。
- 后端中间件预留权限校验位置。

### 16.4 个人维护成本

风险：

- 技术组件过多会增加维护成本。

应对：

- MVP 不引入独立搜索服务。
- MVP 不引入复杂工作流。
- MVP 使用 GORM 提高 CRUD 效率。
- Docker Compose 保持简单。

## 17. 待确认项

- 内部文件服务的上传 URL、鉴权方式、返回字段。
