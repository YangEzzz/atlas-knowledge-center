# 独立文档（2026-10-22）

文档可独立存在，项目关联为选填。新建默认不关联项目，类型默认为“通用文档”；同类型的通用文档可有多篇。项目列表不可用不阻断通用文档写作。文档库、详情、编辑、收藏入口、版本、审计与回收站按文档 ID 工作；查看项目只在有关联时展示。

## 接口与兼容

POST /documents 新增可选 id，projectId 可以为 null。不传 id 创建新文档；传 id 更新该文档，也可关联或取消关联项目。同一项目同一类型的既有约束保留，新建碰到已有文档时拒绝覆盖并提示打开原文档。既有项目/类型的读取接口保留，用于项目详情中的固定入口。历史数据和版本不迁移、不删除。

## 数据库部署

复用 project_documents 表，把 project_id 改为可空，继续保留外键和 idx_project_document_type 唯一索引。PostgreSQL 允许同一类型的多个 NULL 项目。迁移幂等，只放宽字段约束。

先执行迁移，再同时发布前后端；旧前端保存请求没有 id，不适合与新后端长期混用。

在 apps/api 目录使用目标环境配置执行：

~~~text
go run ./cmd/migrate -standalone-documents
~~~

AUTO_MIGRATE=true 的开发环境启动时也执行同一迁移；AUTO_MIGRATE=false 的部署必须显式执行命令。功能验证使用回滚事务。2026-10-22 按用户“全部启动”的要求，已使用现有 Atlas 配置执行此兼容迁移并启动最新 API；既有文档及版本数据保留。

## 验证

- go test ./...：编译与普通回归。
- ATLAS_AUTH_INTEGRATION=true go test ./internal/database -run TestStandaloneDocumentLifecycle -v：专用 atlas_db 内迁移和所有数据变更都回滚，覆盖多篇同类型通用文档、按 ID 更新、列表检索、项目关联/取消、项目冲突不覆盖、版本、审计、删除恢复和已删除项目约束。
- node tests/document-editor.cjs：真实 Vue 页面与内存 API 的浏览器回归，覆盖独立创建、更新、重开、详情、旧项目入口、失败重试、无项目/项目列表失败、图片、键盘和手机布局。
