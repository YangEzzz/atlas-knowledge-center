# Atlas 研发知识中心 PRD

## 1. 产品概述

### 1.1 产品名称

Atlas 研发知识中心

### 1.2 产品定位

Atlas 研发知识中心是面向公司内部研发人员优先使用的项目入口与知识门户，用于统一沉淀公司项目、环境地址、GitLab 仓库、API 文档、原型地址、项目说明、部署说明、FAQ 和开发规范等信息。

第一版重点解决研发人员日常找不到项目资料、环境地址、仓库地址和相关文档的问题，兼顾产品人员使用，并为后续管理层视图、权限系统、GitLab 集成和企微通知预留扩展能力。

### 1.3 背景

当前公司内部项目资料分散在企微、Git、后台系统以及口口相传中。研发人员经常需要通过询问他人来获取测试地址、线上地址、GitLab 地址、项目负责人、接口文档和环境说明，导致信息查找成本高、项目交接困难、文档沉淀不足。

公司规模约两三百人，第一阶段优先服务研发、产品和后续管理层，但当前优先级以研发为主。

## 2. 产品目标

### 2.1 核心目标

- 让研发快速知道公司有哪些项目。
- 让研发快速找到项目的线上地址、测试地址、GitLab、原型和 API 文档。
- 让项目资料以 Markdown 文档形式沉淀在系统中。
- 支持收藏、最近访问、全文搜索，提高日常使用效率。
- 支持文档图片上传、版本历史、软删除和操作审计。
- 预留权限系统、企微通知、GitLab 自动同步、管理层视图等后续扩展能力。

### 2.2 第一版不解决的问题

- 不做 GitLab 自动同步。
- 不做 Excel 导入。
- 不做企微通知。
- 不做文档评论。
- 不做点赞或有用反馈。
- 不做管理层项目报表。
- 不做复杂审批流。
- 不做复杂权限控制，仅预留后续对接能力。

### 5.3 就地维护原则

第一版不拆分前后台两个项目。查看和维护在同一个应用中完成，研发人员在发现信息缺失或错误时，可以在当前页面直接补充或修正。

- 项目管理能力放在项目库和项目详情中。
- 资源入口管理能力放在项目详情的资源入口区域中。
- 文档管理能力放在项目详情和文档库中。
- 工具导航管理能力放在工具导航页面中。
- 文档模板、回收站、操作审计、系统配置放在管理中心中。
- 后续接入权限系统后，通过按钮级和接口级权限控制不同用户可见的操作。

## 9. 文档功能

文档使用 Markdown 编写，并支持图片上传。

### 9.1 文档类型

- 项目介绍
- 环境说明
- 部署说明
- API 说明
- 账号/权限申请说明
- 常见问题 FAQ
- 开发规范

### 9.2 文档字段

- 标题
- 所属项目
- 文档类型
- Markdown 内容
- 摘要，可选
- 创建人
- 更新人
- 创建时间
- 更新时间
- 是否已删除

### 9.3 文档能力

- Markdown 编辑
- Markdown 预览
- 图片上传
- 根据标题自动生成目录
- 文档标题和正文全文搜索
- 文档模板
- 文档版本历史
- 90 天未更新显示“可能过期”

### 9.4 文档版本历史

- 每次保存生成版本记录。
- 可查看历史版本。
- 可恢复到历史版本。
- 记录修改人、修改时间和修改摘要。

### 9.5 文档模板

系统支持按文档类型配置模板。新建文档时，根据文档类型自动带出默认 Markdown 模板。

示例：

```md
## 环境列表

## 访问方式

## 注意事项
```

## 10. 我的私有笔记

我的私有笔记用于存储用户个人敏感或个性化信息，只对当前用户可见。

## 13. 维护与管理

### 13.1 项目维护

- 新建项目
- 编辑项目
- 删除项目
- 恢复项目
- 管理负责人
- 管理别名和关键词

创建项目时最少填写：

- 项目名称
- 项目类型
- 项目简介，可选
- 前端负责人，可选
- 后端负责人，可选
- 测试负责人，可选

项目维护入口：

- 项目库提供新建项目入口。
- 项目详情提供编辑项目入口。
- 项目详情提供删除项目入口。
- 已删除项目进入回收站，由有权限用户恢复。

创建项目后，再进入详情补充资源入口和文档。

### 13.2 资源入口维护

- 新增资源入口
- 编辑资源入口
- 删除资源入口
- 支持默认类型
- 支持自定义类型

资源入口维护入口：

- 项目详情的资源入口 Tab 提供新增、编辑、删除入口。
- 资源入口卡片或列表行提供打开、复制、收藏、编辑、删除操作。

### 13.3 文档维护

- 新建文档
- 编辑文档
- 删除文档
- 查看版本历史
- 恢复历史版本

文档维护入口：

- 项目详情的文档 Tab 提供新建项目文档入口。
- 文档详情页提供编辑、版本历史、删除入口。
- 文档库用于跨项目浏览和搜索文档，同时可进入文档详情。

### 13.4 工具导航维护

- 工具导航页面提供新增、编辑、删除工具导航能力。
- 工具导航卡片或列表行提供打开、复制、收藏、编辑、删除操作。

### 13.5 文档模板管理

- 按文档类型配置模板。
- 新建文档时自动带出模板内容。

### 13.6 回收站

- 查看已删除项目、资源入口和文档。
- 支持恢复。
- 删除采用软删除。

### 13.7 操作审计

审计记录范围：

- 项目创建、修改、删除、恢复
- 资源入口创建、修改、删除、恢复
- 文档创建、修改、删除、恢复
- 工具导航创建、修改、删除、恢复

审计字段：

- 操作人
- 操作时间
- 操作对象
- 操作对象 ID
- 操作类型
- 变更摘要

操作审计入口：

- 项目详情的变更记录 Tab 展示当前项目相关变更。
- 管理中心的操作审计页面展示全局操作记录。

### 13.8 系统配置

- 项目类型
- 资源类型
- 文档类型
- 图片大小限制
- 文档过期天数，默认 90 天

## 14. 权限设计

第一版暂不做复杂权限控制，但预留扩展能力。

### 14.1 第一版原则

- 项目、资源入口、文档默认内部可见。
- 敏感个人笔记仅当前用户可见。
- 创建、编辑、删除权限可先简单处理。
- 后续对接公司已有权限管理系统。

### 14.2 预留字段

- `visibility`
- `owner_id`
- `permission_scope`
- `role_code`
- `department_id`
- `project_group_id`

## 16. 非功能需求

### 16.1 性能

- 首页和项目列表加载应保持快速。
- 搜索结果应在可接受时间内返回。
- 文档标题和正文需要支持全文搜索。

### 16.2 安全

- 个人私有笔记必须用户隔离。
- 后续支持对接统一权限系统。
- 操作审计不可被普通用户删除。

### 16.3 可维护性

- 项目、资源入口、文档均需记录创建人和更新人。
- 删除采用软删除。
- 关键数据支持恢复。

### 16.4 可扩展性

- 后续可接 GitLab 自动同步。
- 后续可接企微通知。
- 后续可增加管理层视图。
- 后续可增加文档评论和反馈。
- 后续可增加项目状态和健康度。

## 18. 验收标准

第一版上线后，研发用户应能完成以下操作：

- 搜索某个项目并进入项目详情。
- 找到项目测试地址、线上地址、GitLab、原型和 API 文档。
- 复制资源链接。
- 收藏常用项目、资源入口、文档或工具导航。
- 查看最近访问内容。
- 创建项目。
- 添加资源入口。
- 编写 Markdown 文档并上传图片。
- 查看文档历史版本。
- 恢复误删内容。
- 查看某项内容的变更记录。

## 19. 后续规划

- 对接公司已有权限管理系统，实现按用户、角色、部门、项目组控制访问。
- 对接 GitLab，自动同步仓库列表、仓库 README 和基础项目信息。
- 对接企微，支持文档过期提醒、项目资料变更通知。
- 增加文档评论、反馈和质量评价能力。
- 增加管理层视图，用于查看项目总览、负责人、资料完整度和项目健康度。
- 增加项目状态管理，如运行中、维护中、已下线、暂停等。
